01 · Situation

Requests need more than a form.

A useful service system has to preserve ownership and state as requests move between the person reporting a problem and the technician resolving it. Without a coherent workflow, statuses and assignments become difficult to trust.

02 · Task

Build the end-to-end workflow.

I built a full-stack application that lets users create service requests, assign technicians, track status, and filter the queue.

03 · Action

Put the business rules into the system.

I designed REST APIs and a layered Controller–Service–Repository architecture with JPA/Hibernate persistence and validation. The React frontend supports intake and technician management. JUnit and Mockito tests cover key service rules.

The rules include blocking resolution without an assigned technician and preventing changes to a closed request. The repository documents the API and local setup.

04 · Result

A working, testable application.

The project demonstrates a complete request lifecycle across the frontend, API, and database. Its code and setup documentation are public.
